Cross-domain behavioural bot detection · measurement record

Mouse-Dynamics Arms Race

A hand-crafted-feature Random Forest trained on 3-second circle-drawing tasks, tested on 40–80-minute admin-work sessions and against synthetic bots that get progressively harder to tell from people. Seven tiers of what transfers, what doesn't, and where the race stands.

DELBOT 3,453 sessions → Balabit 24,182 gap-chunks Weka 3.8.6 RandomForest · 100 trees · seed 1 post-rescale re-baseline · 2026-08-30
Tier 1

Zero-shot transfer

Does a detector trained on one dataset work on a completely different one, untouched?

7 features (num_points, duration_ms, mean/std_velocity, mean_acceleration, mean_jerk, path_efficiency). Train on all of DELBOT, score every real Balabit human gap-chunk, and score matched synthetic-bot twins built from each chunk (endpoints, point count, duration preserved).

The forest learned "fast, jerky motion = bot" from DELBOT's pynput / GAN tools. In the Balabit admin-work domain that same signature belongs to the humans, so the pooled bot AUC sits at or below chance and no operating point catches bots without locking real users out.

Re-baseline: 9 DELBOT files (circles_human_fast) stored coordinates as screen fractions, not pixels — read as pixels their velocities were ~1087× too small. Fixing it moved every DELBOT-trained number slightly; measured by git stash toggling on the frozen reference tools. No conclusion changed.

No cross-domain transfer
Tier 2

Training augmentation

If the training set has no in-domain bots, can synthetic ones stand in?

Held-out Balabit user split (5 train / 5 test, no overlap). Add one synthetic-bot twin per training-user human chunk to the DELBOT training set. BASELINE = 7 features; SCALEFREE = 14 dimensionless features (drops absolute velocity / accel / jerk).

Tier 3

Re-segmentation

Tier 4

The evasive bot

The synthetic bots so far are naive. What about one built to match the feature vector?

AdversarialBotSynthesizer reuses the victim chunk's own (step-distance, Δt) pairs in shuffled order, so the per-step speed multiset — and every permutation-invariant feature — matches by construction. Path = straight line + sine deviations, amplitude tuned so path length matches. AUG_NAIVE = the Tier-2 setup; AUG_NAIVE_PLUS also puts evasive twins in training.

The Tier-2 winner is a coin flip against the evasive bot — it had learned the naive bots' crude tells (velocity scale, over-smooth path), which this bot matches. Putting evasive twins in training recovers detection, but only with the rich feature set: 7 features flag 31% of humans to get there.

Recoverable — rich features required, at an FPR cost
Tier 5

Operating point

Is that 12% human false-positive rate a real defect, or the wrong threshold?

Three-way user split: threshold chosen on CALIB users, every rate measured on disjoint REPORT users. Model = AUGMENTED_SEQ, trained on DELBOT + naive + evasive twins.

Cost-sensitive training and class rebalancing bought nothing (AUC 0.962 / 0.956 vs 0.962 plain). Platt / isotonic calibration cannot help either — they are monotone rescorings and cannot move a point on the ROC curve. A ±10% reject band is a genuine free win: coverage 94%, kept human FPR 0.5%, evasive recall 69%.

New deployment finding: the operating point does not transfer cleanly across users. A threshold set for 1% FPR on calibration users lands at ~1.9% on report users; target 3% → ~5%. Consistent ~1.6–2× slippage — calibrate at roughly half the FPR you actually need.
Threshold artefact — but the operating point slips across users
Tier 6

Ordering features

The evasive bot shuffles the speed sequence. Can a feature read the order the other 20 throw away?

Two dimensionless features: velocity_lag1_autocorr (lag-1 autocorrelation of the per-step speed series) and velocity_step_roughness (mean |Δspeed| / mean speed), over moving steps. Tier6FeatureProbe checks whether the signal exists before trusting the downstream number.

Hand-crafted scalar features on gap-chunk aggregates are exhausted for this adversary.

Tier 7

Round-7 attacker

The ballistic bot doesn't match the ordering statistics — it overshoots, swapping "too random" for "too smooth". Real gap-chunk motion lives in a narrow band between. It still degrades the Tier-4/5 model (evasive AUC 0.96 → 0.86, recall 58% → 16%), and the Tier-6 ordering features give no protection against it — they had learned "jerkier than a human = bot" from the shuffle bot, and the ballistic bot is smoother than a human. A model trained only on ballistic twins is barely better than a coin flip against shuffle (0.72). Training on both covers both, at the same tunable default-threshold FPR cost seen in Tier 4.

Defences are attack-specific — the race continues

The race, in seven moves

  1. A hand-crafted-feature Random Forest does not transfer across datasets (bot AUC 0.44).
  2. Better features don't fix it — richer features make zero-shot worse.
  3. Re-segmentation doesn't fix it either.
  4. Synthetic-bot training augmentation fixes it for naive bots (AUC 0.998).
  5. A feature-matched evasive bot defeats that (AUC 0.53); adversarial training + rich features recovers it (AUC 0.965), and the human-FPR cost is a threshold artefact — ~74% evasive recall at ~3.4% held-out-user FPR.
  6. Reading the shuffled step order back out is a marginal add — the temporal signal the idea assumed isn't present in these chunks.
  7. A second evasion strategy defeats the Tier-5 model (AUC 0.86) and is only covered by training on it too. Defences don't generalise across evasions for free.

Behavioural bot detection with hand-crafted features and trees is a measurable arms race, not a solved problem. The next real lever is a different representation — a trajectory-image CNN, as in Wei et al. — not more scalar features.

Method caveats — state these in the writeup

Not zero-shot from Tier 2 on
The augmented models train on five Balabit users. This is semi-supervised domain adaptation; the human-FPR drop partly reflects having in-domain human examples.
Synthetic bots share one generator family
All test bots come from BalabitBotSynthesizer / AdversarialBotSynthesizer (Bezier, min-jerk, shuffle, ballistic). No captured Selenium / pyautogui traffic, no GAN trajectories.
The arms race is not won
The evasive bots match a subset of features by construction; a bot that also matched accel/jerk ordering and curvature — or hit the human roughness band exactly — would push detection back toward chance.
Latency is asserted, not measured
The sub-millisecond real-time claim has not been timed for the 100-tree forest plus 20-feature extraction.
