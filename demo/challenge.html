    Each sim is handed the answer by a debug route. It assumes a perfect OCR attacker, so only the timing channel is under test. Needs the server started with --oracle.

    Read before quoting this. The thresholds are uncalibrated. Every constant in CaptchaChallenge.Rules is hand-set from first principles — there is no human sample for this challenge, and n=1 is not calibration. They are conservative placeholders. The forest is deliberately not applied here: Tier 3 measured that short goal-directed segments push zero-shot human FPR from 10.85% to 28.85% (7 features) and 32.58% to 71.09% (14), so CAPTCHA hops are the worst possible input for it. This is a second, independent channel with its own scorer; the two scores are never averaged. And this does not make bots impossible. The last attack button passes — a bot that sleeps a jittered human-like delay defeats every rule here today. What the design actually buys is that the attacker is forced online and serialised: it must solve each hop live, in order, inside a window it cannot shrink. That is a throughput tax, not a classification guarantee — the same "defences are attack-specific" conclusion the seven tiers reached, one level up.
